# Live Darshan — Phase 1 build contract

Status: build contract, 2026-09-14. Every builder follows this file; where it and the code disagree, this file wins; where it is silent, follow `docs/live/PHASE0-ANALYSIS.md` and the existing conventions (docs/payments/SPEC.md §10–§13 for admin/test style). Later phases have their own contracts; **nothing from Phase 2+ is built here.**

## 0. Decisions taken (recommended options from PHASE0 §8; the client asked us to proceed without waiting)

1. Admin management = a PHP admin page **and** the requested JSON routes `GET/POST/PUT/DELETE /api/admin/live-streams(/:id)`, both calling the same store functions (one write path).
2. `temples` and `deities` become small seeded tables; every other module keeps treating the temple as a constant.
3. "Live Darshan" is added to the header `NAV_LINKS`, the drawer (automatic), the footer quick links, site search and the chatbot facts. The Frontend builder must run the existing header-fit check (tests/public-e2e.mjs "header fits" at 30 widths); if the 1024–1280 band overflows, drop the header entry and keep drawer + footer + homepage tile.
   **Outcome (review, 2026-09-15).** The stage-B check measured spill outside `.navbar__inner` only; the nav clips its own overflow, so the review's measurement (labels against the nav box and the right cluster) found the eight Tamil labels (724 px) clipped in three bands: 1024–1059 (first/last label cut, −4 px), 1400–1559 (the seva CTA appears at 1400 and left the nav 661–701 px) and ≥1560 (the brand widened to 300 px, nav 648 px, 38 px lost at each end). Without the entry every width fits. Decision: the entry stays, and the header's own priority order is applied in Tamil only — the `/live-darshan` link (`navbar__link--optional`) is hidden at 1024–1059 px in both languages (footer, Home tile and search carry it; the drawer takes over below 1024); in Tamil the seva CTA waits until 1440 (it "is the first thing to go"), the brand keeps 240 px at ≥1560 (it "truncates gracefully while a clipped nav item does not") and the nav pills take 0.45rem side padding from 1201 px (the row already uses 0.5/0.42rem below 1200). English is unchanged apart from the 1024–1059 hide. Measured nav→controls gap with the entry after the change, Tamil: 2560:30 1920:30 1600:30 1560:29 1559:86 1440:27 1439:102 1400:82 1366:65 1280:29 1200:56 1100:33 1060:13, and 1024–1059 without the entry 50–67; English 77–156 everywhere. `tests/live-ui.mjs` "Header fit" now measures clipping inside the nav at 36 widths in both languages and asserts the entry is shown from 1060 px.
4. Player: the YouTube iframe is mounted as soon as the page knows the stream is LIVE or STARTING (no autoplay parameter in Phase 1 — the YouTube player's own play control is used; this respects mobile autoplay policy and reduced motion). SCHEDULED / OFFLINE / ERROR / COMPLETED / CANCELLED show a poster card with the state text instead of an iframe.
5. The temple's YouTube channel handle is unknown (`@TempleMahendra` is 404). Keep `TEMPLE.youtube` in `frontend/src/data/temple.js` as a **single constant** (`{ channelUrl: "https://youtube.com/@TempleMahendra" }`) used by the fallback link; the homepage tile now goes to `/live-darshan`. Changing the handle later is one line.
6. UTC everywhere in the database; the admin schedules in the stream's timezone (default Asia/Kolkata).
7. No YouTube network calls in Phase 1 (no API key, no oEmbed); the embed is built from the validated video id. The provider interface still exists so Phase 3 slots in.
8. Nothing is committed to git by any builder.

## 2. Transitions (`LIVE_TRANSITIONS`, enforced in `liveSetStatus()`; the same table serves the page, the JSON API and Phase 3)

| From | To (admin, Phase 1) |
|---|---|
| DRAFT | SCHEDULED, CANCELLED |
| SCHEDULED | STARTING, LIVE, CANCELLED, DRAFT |
| STARTING | LIVE, OFFLINE, CANCELLED, SCHEDULED |
| LIVE | COMPLETED, OFFLINE |
| OFFLINE | LIVE, COMPLETED, ERROR |
| ERROR | SCHEDULED, LIVE, CANCELLED |
| CANCELLED | SCHEDULED, DRAFT |
| COMPLETED | (none) |

Readiness: entering **SCHEDULED, STARTING or LIVE** (`LIVE_VALIDATED_TARGETS`, from any status) additionally runs `liveValidate()` on the stored row with the target status inside `liveSetStatus()`; a row without a video id (a custom provider: without a playback URL) or a start time — or with any other field error — is refused with `LiveValidationException` (`->fields`, the §4.2 map) and nothing changes. The page shows the fields as one error flash ("Cannot publish yet: …", "Cannot go live yet: …"), the API answers `422 {error, fields}`, and the row menu does not offer Publish / Starting soon / Go live while `liveReadyToPublish($row)` is false (the Status cell says "Add a video ID and a start time to publish"). DRAFT → CANCELLED and the other non-public targets need no video id. The `/live` list orders LIVE by `COALESCE(actual_start_at, scheduled_start_at)` **descending** (the most recently started broadcast is the one the page features), then STARTING soonest first.

Effects: first entry into LIVE sets `actual_start_at = UTC now` if NULL; COMPLETED sets `actual_end_at` if NULL; every change writes `liveAudit('live_stream_status', 'Stream #<id>', 'from → to by <user> — “<title_en>”')` (the `from → to by <user>` prefix is the contract; the title suffix, ≤120 characters, is informative) and `updated_by/updated_at`. Saving the form with a different `status` value goes through the same function (an illegal jump is a validation error "That status change is not allowed").

### 4.2 Validation contract (`liveValidate`)
Field keys (used by the page inputs, the JSON API body and the error map):

| Key | Rule |
|---|---|
| `title_ta`, `title_en` | required, 2–300 code points after `sanitizeText` |
| `description_ta`, `description_en` | optional, ≤ 5000 |
| `slug` | optional on create (auto from `title_en`), editable; validated against the regex, reserved list and uniqueness (case-folded) |
| `temple_id` | required, active temple |
| `deity_id` | optional, belongs to that temple |
| `event_type` | in `LIVE_EVENT_TYPES` |
| `provider` | in `LIVE_PROVIDERS`; only `youtube`/`custom` accepted for saving in Phase 1 (others: "This provider is not available yet") |
| `provider_reference` | for youtube: required unless status is DRAFT; parsed with `parseReference` → stored in `provider_broadcast_id`; for custom: `playback_url` required instead |
| `playback_url`, `thumbnail_url`, `banner_url` | optional; `liveSafeUrl`; uploaded files (page only) win over the URL field when both are given |
| `scheduled_date` + `start_time` + `end_time` + `timezone` | timezone via `liveIsTimezone` (default Asia/Kolkata); date `Y-m-d`; times `H:i`; start required unless DRAFT; end optional, must be after start (same date, or `end_date` may be given for overnight streams — accept an optional `end_date`); converted with `liveToUtc` |
| `status` | in `LIVE_STATUSES`; on create only DRAFT or SCHEDULED; on update must be a legal transition from the stored status (or unchanged) |
| `is_featured`, `show_on_homepage`, `donations_enabled`, `notifications_enabled`, `sharing_enabled`, `archive_enabled` | checkbox semantics (`publicGuardConsent`-style truthy: `true`, `1`, `"1"`, `"true"`, plus `"on"` because a bare HTML checkbox posts `on`; anything else, including `"yes"` and arrays, is false) |

Non-object bodies, arrays where strings are expected, oversized input, `9999-99-99`, `javascript:` URLs, `"><script>` in any field → a field error, never a 500, and the typed values are kept on re-render.

### 4.3 Public API (`backend/api/index.php` block before `$routes`)
```php
if (preg_match('#^/live-streams(?:/(live|upcoming|[0-9]{1,10}|[a-z0-9][a-z0-9-]{1,118}))?$#', $path, $liveMatch)) { $liveRoute = $liveMatch[1] ?? 'index'; require __DIR__ . '/live_streams.php'; exit; }
if (str_starts_with($path, '/live-streams/')) sendError('Not found', 404);
if (preg_match('#^/admin/live-streams(?:/([0-9]{1,10}))?$#', $path, $liveAdminMatch)) { $liveAdminId = isset($liveAdminMatch[1]) ? (int) $liveAdminMatch[1] : null; require __DIR__ . '/admin_live_streams.php'; exit; }
if (str_starts_with($path, '/admin/')) sendError('Not found', 404);
```
`live_streams.php`: guard `$liveRoute` when hit directly (404 JSON), GET/HEAD only (405 + `Allow: GET, HEAD`), `Cache-Control: no-store, private` for `live` and `index`, `public, max-age=60` for `upcoming`/id/slug; `liveTablesExist()` false → `{"streams":[],"server_time":…}` / 404. Responses:
- `index` → `{ live: [...], upcoming: [...], server_time }`
- `live` → `{ streams: [...], server_time }` (LIVE first, most recently started leading — `COALESCE(actual_start_at, scheduled_start_at)` DESC — then STARTING soonest first)
- `upcoming?limit=` (default 10, max 50) → `{ streams: [...], server_time }` (SCHEDULED rows not yet over per §1 "upcoming", soonest start first)
- `<id>` / `<slug>` → `{ stream: {...}, server_time }`; digits = id; unknown/DRAFT/deleted → 404 `{"error":"Not found"}`

Public item shape (`liveShapePublic`): `id, slug, title_ta, title_en, description_ta, description_en, event_type, event_type_label {ta,en}, provider, status, is_live (bool), temple {slug, name_ta, name_en, short_name_ta, short_name_en}, deity {slug, name_ta, name_en} | null, scheduled_start_at, scheduled_end_at, actual_start_at, actual_end_at (ISO-8601 UTC or null), timezone, local {date, start_time, end_time, end_date} (wall clock in `timezone`; `end_date` is non-null only when the end falls on a later day than `date`, for overnight streams), thumbnail_url, banner_url, playback {kind, embedUrl, watchUrl}, flags {featured, showOnHomepage, donations, notifications, sharing, archive}`. Never `provider_stream_id`, `created_by`, `updated_by`, `deleted_at`, internal ids of temple/deity.

### 4.4 Admin JSON API (`backend/api/admin_live_streams.php`)
- `require_once __DIR__ . '/../includes/auth.php'` (starts the session, loads `.env.local`), then **re-install** the API JSON exception/error handling (`set_exception_handler` to a JSON 500 with reference; `set_error_handler` that logs and continues for warnings) because `errors.php` installed HTML handlers; `ini_set('display_errors','0')`.

- Headers: `Cache-Control: no-store, private`, `X-Content-Type-Options: nosniff`; CORS **not** widened (do not call `setCorsHeaders` with credentials; same-origin only). Never sets cookies itself.
- Routes: `GET /api/admin/live-streams?f=&q=&sort=&dir=&page=` → `{ streams: [adminShape…], total, pages, page, csrf }`; `GET /api/admin/live-streams/:id` → `{ stream }`; `POST` (JSON body with the §4.2 keys) → `201 { stream }` or `422 { error, fields }`; `PUT /:id` → `200 { stream }` / `422` (field errors, a locked slug, or a row not ready for SCHEDULED/STARTING/LIVE — `LiveValidationException` is answered as the same `{ error, fields }` shape) / `404` / `409 { error, code:"transition" }` for an illegal status jump; `DELETE /:id` → `200 { success:true }` (soft delete; already deleted → 404). Admin shape = public shape + `created_by, updated_by, created_at, updated_at, deleted_at, provider_broadcast_id, playback_url_raw, thumbnail_url_raw, temple_id, deity_id` (`*_raw` = the stored URL as typed, before the provider's default is applied). - Every write goes through `liveInsert/liveUpdate/liveSoftDelete/liveSetStatus` → audited with the signed-in username.
